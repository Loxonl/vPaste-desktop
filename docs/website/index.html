The second chance after copy

vPaste is built around recovery, not just collection.

A useful clipboard manager needs more than a long list. It needs fast recall, readable previews, clear source context, and a paste path that does not pull you out of the active app.

Alt

Open, choose, paste

Global shortcut, arrow keys, Tab, Shift+Tab, Alt number hints, Ctrl+F search, Space preview, Esc close.

Find

Search the useful parts

Search text, rich fallback text, cached link titles, file paths, colors, and highlighted matches in result cards.

Pin

Keep recurring work close

Favorites and custom tabs organize by type, source app, favorite state, and time range without hiding the full history.

Zip

Move history between setups

Export and import history packages, rebuild search indexes, and keep tabs and rich formats usable after migration.

What vPaste already covers

The clipboard categories that matter in real Windows work.

Paste, Ditto, CopyQ, and EcoPaste all make the same point: people need history, search, organization, shortcuts, and support for more than plain text. vPaste focuses those ideas on a native Windows flow with rich preview and recovery detail.

History

Old items move forward when reused

Activating an older record puts it back at the front, so frequently reused content naturally stays within reach.

Source

App names and icons are part of the memory

Cards can show the source app, high-resolution icon, app-colored header, timestamps, and favorite state.

Actions

Right-click work stays near the item

Favorite, preview, export image, open or copy containing folder, convert colors, paste rich text as plain text, and delete.

Personalization

Search, tab, and scroll behavior can stay optional

vPaste keeps fast defaults, then lets users decide whether search state, swipe position, and tab position should persist.

Performance

Large histories need quiet engineering

Memoized cards, merged wheel events, throttled refreshes, persistent thumbnails, and background image warmup keep browsing responsive.

Settings

A desktop utility should behave like one

Language, theme, launch at login, onboarding, data directory, import, export, cleanup, tray behavior, shortcuts, and about details belong in a real settings window.

Preview before you paste

Every item carries enough context to choose confidently.

A record can be plain text, a formatted table, a chat message with images, a screenshot, a folder path, or a link whose title loads later. vPaste keeps the card readable and opens a larger preview when needed.

Format coverage

Not all clipboard data is text, so vPaste does not treat it that way.

The public docs call out what is supported now and where the work is still being hardened.

Plain text

Unicode text, multiline notes, logs, code

Searchable, highlightable, scrollable, and available for plain-text paste.

Supported
Links

URLs with cached title, preview image, favicon

Async refresh, title search, fallback icon, and retry cooldown are already in the product direction.

Supported
Images

Screenshots, image files, PNG, transparent PNG, GIF cases

Cards show thumbnails and resolution; preview, paste, and export read originals only when needed.

Hardening
Files and folders

Single file, folder, multiple files, invalid path checks

Show the path tail first, detect missing sources in the display area, and open or copy containing paths.

Hardening
Rich formats

HTML Format, RTF, PNG, text fallback

Excel tables, OneNote blocks, web fragments, and chat messages are tested for readable cards and reliable restore.

Hardening
Sensitive formats

System-marked private clipboard content

Sensitive clipboard content is skipped by default, with app and window blacklist work planned after the safety model is stable.

Local-first by design

Clipboard history should not leave your machine by default.

vPaste stores history, images, rich formats, tabs, previews, icons, and search metadata in the configured local history directory. Encrypted history and sensitive-content skipping remain product-level requirements.

Transparent roadmap

Clear about what is next, careful about what is promised.

Future work is tracked separately from current support. These items should be treated as planned direction until they land in release notes.

Search

Advanced query filters

Type, app, favorite, date, and suffix syntax are planned on top of existing custom tab filters.

Paste flow

Batch paste and paste queues

Multi-select and ordered paste are tracked as future work, not current release behavior.

Commands

Local commands, scripts, plugins
